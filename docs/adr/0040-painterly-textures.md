# 0040. Painterly textures: one data-driven stroke generator, baked at build time, behind a switch

- Status: Accepted (2026-10-20: the owner's art brief; the painterly set stays behind
  `?textures=painterly` until the owner approves it as the default)
- Date: 2026-10-20
- Builds on: [0027](0027-webgpu-renderer.md) (the atlas on wgpu), [0036](0036-render-modes-and-cross-geometry.md)
  (cutout tiles, the tall grass sprite), [0038](0038-block-registry-sync.md) (the `missing` tile)
- Design: [`PAINTERLY_TEXTURES.md`](../PAINTERLY_TEXTURES.md); style: [`ART_DIRECTION.md`](../ART_DIRECTION.md)
- Related: 0041 (characters), which uses this palette and these materials

## Context

The owner set Dwell's first art direction (2026-10-20): a bright, hand-painted storybook look, with
every texture (blocks, plants, water, sky accents, characters) generated by one procedural
generator, driven by data. The block tiles were hard-coded noise painters in `dwell-mesh`
`textures.rs`, one Rust function per tile with its colours as constants. Nothing could add or
retune a tile without code, and nothing shared colours with the coming characters. Value noise at
four octaves also reads as speckle at a distance, the noise the brief asks to avoid.

## Options considered

- **Where the generator runs.**
  - (a) In Rust at load time, from JSON embedded in the build.
  - (b) In a Node script at build time, with the baked texels checked in.
  - (c) On the GPU per pixel.

  (c) costs frame time and needs the vocabulary in WGSL. (a) needs a second implementation for
  the editor page and the character prototypes, which are JavaScript. (b) keeps one implementation
  (a dependency-free ES module) for the bake, the editor and the prototypes. The client only copies
  bytes, with the same CI stale check as the other generators.
- **How the output feeds the renderer.**
  - (a) A second atlas.
  - (b) The same atlas, with each painted tile's texels replacing its classic painter.

  (b) leaves the meshes, the tile rectangles, the mip chain, the coverage-preserving cutout mips,
  the LOD averages and the shaders untouched.
- **The vocabulary.**
  - A general image-processing graph (noise, blur, masks).
  - A small fixed set of painted marks: fill, gradient, dab, streak, blade, slab, ring and edge
    light, with placement by a jittered grid or exact positions.

  The marks are what "broad clean strokes" means, a tool can edit them as numbers, and they can't
  produce speckle by accident.
- **Colours.**
  - Hex in each material.
  - A shared palette of named three-stop ramps (shadow, base, light), referenced by name.

  The ramps make one palette for the world and the characters, and let a template be recoloured
  by its ramp.
- **The switch.**
  - Replace the look.
  - A build flag.
  - A runtime choice by URL.

  The owner must approve before players see it. A URL choice (`?textures=painterly`) works in every
  build, including the published one, for review. Flipping the default is one line.

## Decision

- `shared/textures/palette.json` (ramps and swatches) and `shared/textures/materials.json`
  (materials: use, ramp, overlay, wrap, alpha, `like` templates, `over` stacking, layers; and the
  atlas tile each block material paints) are the source of truth.
- `shared/textures/paint.mjs` is the generator. `shared/textures/gen.mjs` validates the data against
  the registry's tile names and bakes the block tiles into `crates/dwell-mesh/src/painterly.rgba`
  and `painterly.gen.rs`, checked in. CI regenerates them, fails on a diff and runs
  `gen.test.mjs`, which adds a material by data alone.
- `dwell-mesh` has a `TextureSet` (`Classic` and `Painterly`, the default since the owner approved it on 2026-10-20). One texel lookup serves
  the atlas, cutout detection, the tile averages (LOD colours) and the hotbar swatches. Tiles the
  painterly set does not paint (`plain`, `grid`, `missing`) keep their classic painter.
- `?textures=painterly` sets it on the page before the atlas is built, and in each meshing worker
  through its init message, so LOD colours match the atlas.
- The editor page is `docs/prototypes/painterly-texture-lab.html`.
- Textures are not public API: no world format, protocol or terrain change, so a patch release.

## Consequences

- New materials, new colours and retuned strokes are data edits. A new stroke kind is a small
  change to `paint.mjs` and its validator.
- The characters (0041) read materials and ramps by name from the same files.
- The classic painters stay in the code until the owner flips the default. After that, they can be
  removed, with their tests moved to the painterly set, or kept as an option.
- Tiles stay 32 texels. Finer brushes need a 64-texel atlas (`TILE`), a separate change.
- The frame cost is unchanged: the same atlas, meshes and shaders. Start-up copies baked tiles
  instead of running noise.
- Reversal: drop `shared/textures`, the generated files, `TextureSet` and the init field. The
  classic painters are untouched.
