# Controller support **[built, 0.28.3]**

Owner (2026-10-26): "Add controller support." Chosen with the owner:

- **Players remap in Settings.** Default bindings ship in a data file; players rebind buttons and
  set the look speed and inverted Y in Settings → Controller, kept per browser.
- **Gameplay and menus.** Everything you do in the world, and the game menu and the main menu by
  D-pad (or left stick) and A/B.

## 1. Data

`shared/input/gamepad.json`, validated and generated by `shared/input/gen.mjs` into
`crates/dwell-game/src/gamepad.gen.rs` and `client/src/input/gamepad.gen.ts` (CI fails on stale
output):

| Key | Holds |
|---|---|
| `buttons` | The W3C Standard Gamepad's buttons: name, label (shown in Settings), index (0–16) |
| `sticks` | The axes: `moveX`, `moveY` (left stick), `lookX`, `lookY` (right stick) |
| `play` | Each play action's default button |
| `menu` | Each menu action's button |
| `tunables` | `deadzone` 0.15, `lookDegPerS` 220, `lookCurve` 2, `triggerThreshold` 0.4, `menuRepeatMs` 140, `menuRepeatDelayMs` 380 |

Validation: every action bound once, to a known button; no button twice in a group; tunables in
range; unknown keys fail with their path.

Default play bindings: A jump (fly up), B crouch (fly down), left stick press run, RT break, LT
place, RB / LB next / previous block, Y fly, D-pad up / down fly faster / slower, X spyglass, View
map, Menu the game menu. Menus: D-pad (or left stick) moves the focus, A presses, B goes back, Menu
closes the game menu.

## 2. Engine (fixed vocabulary)

- **Play** (`dwell-game` `gamepad.rs`, platform-free like `input.rs` and `touch.rs`): `PlayAction` —
  jump, crouch and run are held (run latches on its press until the move stick lets go); the rest act
  on the press. The left stick moves (radial dead zone, rescaled to full tilt); the right stick turns
  the view at `lookDegPerS × lookSpeed × tilt^lookCurve` per second, right turning right on each
  face (`FaceFrame::handed`, as the mouse) and scaled by the spyglass as the mouse is. Its move and
  held buttons join the keys and touch in `KeyboardMouseInput::sample`. While a menu is open
  (`setMenuOpen`) nothing acts or is held, but the buttons are tracked, so one held over closing the
  menu isn't a press.
- **WASM** (`web/app.rs`): `gamepad(buttons, axes, now)` each frame (actions: break and place as
  clicks, the hotbar as the wheel, fly as F, fly faster/slower one level, the spyglass, the map as
  F4; returns `pause` for the shell), `gamepadDisconnected`, `setGamepadBinding`,
  `resetGamepadBindings`, `setGamepadLook`, `gamepadBinding`.
- **Menus** (`client/src/input/gamepadMenu.ts`): the reachable controls are the open modal
  dialog's (the game menu, `aria-modal`), else the page's; a direction moves the focus to the
  nearest control that way (distance along it plus twice across: `nearestToward`), repeating while
  held; left and right step a slider or a select; A clicks; B is back (closes the game menu; Esc on
  the main menu page); Menu closes the game menu.
- **Poller** (`client/src/input/gamepad.ts`): every animation frame, the first connected pad (a
  standard-mapped one first) goes to the WASM client, and to the menu while one is open; in Settings
  a rebinding takes the next button newly pressed (`capture`). The main menu page (the launcher's
  too) runs a menu-only poller (`startMenuGamepad`).

## 3. Player settings

`client/src/input/gamepadSettings.ts`, key `dwell.gamepad`: `bindings` (action → button name),
`lookSpeed` (0.25–3) and `invertY`. Sanitized on load (unknown names dropped, clashes resolved, each
action on its own button); append-only on save (fields a newer build wrote are kept, bindings
included). Rebinding an action to a button swaps it with the action that had the button, in the
settings and in the engine alike. Settings → Controller (`ui/controllerPanel.ts`) lists the actions
with their buttons, the look speed and invert Y, Reset, and whether a controller is connected.

## 4. Tests

- `shared/input/gen.test.mjs`: the data validates; a binding changed by data alone is emitted; bad
  entries fail naming the key.
- `dwell-game` `gamepad.rs`: defaults from the data; presses act once and held buttons hold; the
  trigger threshold; nothing acts with a menu open or on closing it; the dead zone and full tilt;
  the right stick turns like the mouse on both faces (`both_faces!`) and inverted Y; run's latch;
  rebinding swaps. `input.rs`: the controller joins the keys and touch in the sample.
- `client/src/input/gamepad.test.ts`: settings defaults, swap, sanitizing, the append-only record;
  the focus picking, the repeat, the menu's reading, the pad picked.
- `client/e2e/gamepad.spec.ts`: a scripted controller (`navigator.getGamepads` replaced) walks the
  player, opens the game menu with Menu, moves its focus with the D-pad and closes it with B.
